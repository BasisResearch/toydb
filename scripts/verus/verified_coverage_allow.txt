# verified_coverage_allow.txt -- known-dead verified exec surface.
#
# One key per line, optionally followed by a free-form reason. A key is either a
# module path (sql::parser::verified_stmt) or a module::function qualifier
# (sql::parser::verified_roundtrip::parse_expr_exec). A flag is suppressed when
# its own key OR its module is listed. `#` lines and blanks are ignored.
#
# Every entry is a verified twin/helper that neither production nor the lib test
# suite executes. It is kept (not deleted) until phase 4 ("delete-twins") retires
# the dead parsers and their oracle. Removing a line here WITHOUT deleting the
# corresponding code makes `verified_coverage.py --check` fail, which is the
# intended ratchet.
#
# The set below was produced on branch kg/parser-fix-phase-1-coverage from a real
# `cargo llvm-cov test --lib` run joined against `verify.sh --output-json`
# func-details; it is exactly the dynamic flag set. Cleared by: phase 4.

# --- wholly-dead modules (every exec function is a twin production never calls) ---

# The full round-trip-proven statement parser. parse_stmt_exec /
# parse_stmt_full_exec are twins of verified_control::parse_control_at, which is
# what production actually calls; the ~65 print_*/exec_* helpers only feed them.
sql::parser::verified_stmt

# The verified lexer. Production lexing goes through the hand-written `Lexer`
# (super::Lexer::new). The only exec function it borrows is the self-contained
# scan_symbol_bytes (lexer.rs:556) -- which IS covered, so it is never flagged.
# Every other exec function here (lex_all_exec, lscan_token_exec,
# classify_kw_exec, ...) is a dead twin of the hand-written scanner.
sql::parser::verified_lexer

# The standalone stream-based scanner/parser (next_token / PeekStream / parse_*
# over &[u8]/&[Token]). Superseded by the verified_precedence + verified_control
# production path; nothing calls it.
sql::parser::verified
